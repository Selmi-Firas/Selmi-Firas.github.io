SIEM — Enterprise Security


Proposed and deployed a full SIEM (Security Information and Event Management) solution for an enterprise environment — combining Snort, the ELK Stack, and Wazuh to deliver real-time log collection, event correlation, threat detection, and centralized alerting from a single Kibana interface.

— Problem Statement —

The target enterprise suffered from an absence of robust security infrastructure: no IDS/IPS, insufficient network monitoring, and no centralized visibility over security events. Firewalls and antivirus alone proved insufficient against evolving attack vectors. The goal was to implement a SIEM that provides real-time detection, correlation, and an organized alert workflow to support faster incident response.

— Pipeline Architecture —

Snort — Network Intrusion Detection System (NIDS). Deployed to monitor all incoming and outgoing network traffic in real time. Operates using a preconfigured rule set; custom rules created and validated to match specific threat signatures. Alerts are written to log files and forwarded downstream into the ELK pipeline.
Filebeat — Lightweight log shipper installed on monitored servers. Reads Snort alert logs and system logs, then forwards them to Logstash for processing. Configured with input and output modules to specify sources and destinations.
Logstash — Event processing engine. Receives logs from Filebeat, applies filtering and enrichment (parsing fields, adding metadata, normalizing timestamps), and outputs structured events to Elasticsearch for indexing.
Elasticsearch — Distributed search and storage engine. All security events from Snort, Wazuh, and system logs are indexed here, enabling sub-second queries across millions of events for correlation and investigation.
Kibana — Primary visualization and investigation interface. Dashboards display real-time alert feeds, traffic volume graphs, attack timelines, and geographic source maps. Snort alerts are rendered directly in Kibana with full event context.
Wazuh Manager — Centralized HIDS management server. Collects security telemetry from all connected agents, analyzes events against a rule database, and forwards findings to Elasticsearch via Logstash.
Wazuh Agent (Windows) — Installed on Windows endpoints to monitor Windows Event Logs, registry changes, file integrity, and authentication events. Reports in real time to the Wazuh Manager.
Wazuh Agent (Linux) — Installed on Linux servers to monitor syslog, auth.log, file system integrity, and process activity. Reports in real time to the Wazuh Manager.

— SIEM Functional Capabilities —

• Real-time collection of logs and events from network and host sources.
• Normalization and enrichment of raw data into a structured, queryable format.
• Correlation of events across multiple sources to surface patterns indicating attacks.
• Automated alert generation with severity classification.
• Full audit trail and archiving for compliance and forensic investigation.
• Security dashboards and reports for operational visibility.

— Attack Detection: Brute-Force SSH —

A live brute-force SSH attack was simulated against a Linux server to validate the full detection pipeline. Wazuh agents on the target machine detected repeated failed authentication attempts and triggered alerts. Snort captured the corresponding network traffic pattern and generated IDS alerts. The full attack chain — connection attempts, authentication failures, source IP — was visible end-to-end in the Kibana dashboard within seconds of the attack starting.
