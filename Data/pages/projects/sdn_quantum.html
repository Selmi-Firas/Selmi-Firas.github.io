SDN — Distributed Quantum


Designed and implemented a modular SDN Controller for Distributed Quantum Computing — an intelligent orchestration system that manages the execution of quantum workloads across a network of heterogeneous quantum nodes, simulated using NetSquid.

— What Problem Does It Solve? —

Current quantum hardware is limited in the number of qubits a single device can reliably host. Distributing computation across multiple networked quantum nodes is the natural path forward — but it introduces a critical challenge: every node and every link in the network behaves differently. Coherence times vary, fiber channels introduce photon loss, and hardware degrades unpredictably. A static, hardware-blind scheduler will inevitably assign work to degraded or failing nodes, causing computations to fail silently. This SDN controller solves that problem by treating the quantum network the same way classical SDN treats a data network — monitoring hardware state in real time and making intelligent, adaptive routing and scheduling decisions.

— Architecture: 7-Module Controller —

Monitor — Continuously benchmarks every node in the network. Runs hardware fidelity tests and link delivery tests, then combines results into a single quality score per node. Nodes that fall below a usability threshold are automatically excluded from assignment.
Watchdog — Reads the Monitor's link health data and sets binary HEALTHY / DEAD alerts per link. Any link flagged as dead is never used for quantum operations — preventing silent failures mid-computation.
NodeAssigner — Ranks all surviving nodes by quality score and assigns the best available nodes to computation roles. Filtered by usability thresholds and the RecoveryEngine's blacklist to ensure only reliable hardware is used.
Translator — Converts abstract circuit operations into concrete network actions. Implements EDF (Earliest Deadline First) scheduling — operations on qubits with the least remaining coherence time are always prioritized first, minimizing decoherence-induced errors.
Executioner — The low-level execution engine. Interfaces directly with the NetSquid simulator API to perform all quantum network primitives: entanglement generation, Bell state measurements, corrections, and gate application.
RecoveryEngine — Implements cross-run learning. Tracks each node's historical success rate, identifies chronic failure sources, and blacklists them from future assignments. The node ranking improves with every run — the controller gets smarter over time.
Controller — The master orchestrator. Coordinates all six modules across two phases: a Boot phase that scans hardware and builds the node assignment, and a Run Loop that executes the quantum workload using the current assignment.

— Key Technical Features —

• Real-time hardware telemetry — the controller knows the current health of every node and link before committing any operation.
• Quality-ranked node selection — computation is always assigned to the best available hardware, not the nearest or most convenient.
• Deadline-aware scheduling (EDF) — quantum coherence windows are respected, reducing decoherence errors on time-sensitive qubits.
• Inline entanglement purification (DEJMPS) — when link fidelity drops below threshold, the controller automatically runs a purification protocol to recover quality before proceeding.
• Cross-run learning — node reliability scores are updated after every run, progressively improving assignment decisions over time.
• Fault isolation — degraded nodes (like a node with a coherence time 200× shorter than healthy nodes) are automatically detected and excluded without manual intervention.

— Results —

The SDN controller achieved a +7% improvement in computation success rate compared to a hardware-blind baseline that performed all the same quantum operations but without any monitoring, quality scoring, scheduling intelligence, or purification. The result demonstrates that in distributed quantum computing, how the network is orchestrated matters just as much as the quantum operations themselves.
