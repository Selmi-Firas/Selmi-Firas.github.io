Automated Deployment — Ansible


Engineered a complete Ansible automation pipeline from scratch to handle multi-machine configuration, software deployment, and file management across a heterogeneous academic lab environment of 30 Windows endpoints and 1 Linux server hosting 12+ VMs — replacing a fully manual process that previously took hours.

— Context —

At Grand Valley State University, the Systems & Network Administration role required maintaining a lab environment serving 4–5 concurrent classes per week with 20+ students each. Each class session required a consistent, pre-configured software environment across all 30 Windows workstations. Before automation, setting up or reconfiguring these machines was done entirely by hand — a process prone to inconsistency, human error, and significant time investment.

— What Was Automated —

Software Installation — Ansible playbooks handle installation of all required applications across all 30 machines simultaneously using WinRM remote execution. A single command triggers deployment across the entire fleet.
File Transfer & Synchronization — Automated distribution of lab files, configuration templates, and resources from the central Linux server to all endpoints. Ensures every student receives identical starting conditions.
System Configuration — Configures Windows settings, environment variables, and application preferences across all machines to guarantee 100% consistent environment setup on every run.
Application Deployment Pipelines — Structured reusable Ansible roles for different deployment scenarios — enabling rapid reconfiguration between different class labs without starting from scratch.

— Results —

Large deployment time: 5–6 hours → under 1 hour
Standard task time: ~1 hour → 30 seconds
Human error rate: Eliminated — all processes are scripted, version-controlled, and repeatable
Consistency: 100% identical environment across all 30 machines on every deployment run
Overall time reduction: Over 95% across all deployment operations

— Technical Design —

Playbooks were structured using Ansible roles for modularity — separating software installation, file transfer, and configuration tasks into independent, reusable components. Windows connectivity was handled via WinRM (Windows Remote Management), with Ansible configured to authenticate over HTTPS using local admin credentials. The Linux server acted as the Ansible control node, executing all playbooks and maintaining the inventory of 30 Windows hosts. All playbooks were written in YAML and stored in a Git repository for version control — enabling rollback and change tracking.

— Infrastructure Managed —

1 Linux server hosting 12+ VMs  •  30 Windows workstations  •  30 VirtualBox instances each running 3+ VMs  •  90+ total VMs under management
