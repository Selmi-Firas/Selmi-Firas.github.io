SDN — Distributed Quantum


Designed and implemented a 7-module SDN controller for orchestrating distributed quantum computing workloads across a heterogeneous network of quantum nodes simulated using NetSquid. The system was validated by executing Shor's algorithm (N=15) — factoring 15 into 3 × 5 — across the distributed topology, achieving a +7% improvement in success rate over a hardware-blind greedy baseline.

— Why Distributed Quantum Computing? —

Current quantum hardware is limited by the number of physical qubits a single device can reliably host. Distributing a quantum circuit across multiple networked nodes — connected via quantum entanglement and teleportation — allows algorithms that exceed single-device capacity. However, this introduces a fundamental challenge: each link and node is a stochastic source of noise. A naive, hardware-blind scheduler fails because it cannot account for varying coherence times, fiber attenuation, and per-node SPAM errors. The SDN controller solves this by treating the quantum network like a classical SDN: monitoring hardware state in real time and making intelligent routing decisions.

— Network Topology —

A 17-node star topology was constructed in NetSquid with a central switch and 16 leaf nodes. Every node received randomized hardware parameters: T₂ coherence time (range: 5 µs to 1 s), photon emission fidelity, SPAM error rates, and fiber segment lengths (5–20 km). Node-16 was deliberately force-degraded (T₂ = 5 µs) to stress-test the controller's fault tolerance. Fiber segments include realistic photon loss modelled via exponential attenuation.

— Controller Boot Phase —

Before any circuit execution, the controller runs a full hardware scan:

Test 1 — Local Coherence Test: For every node, a Bell state is created between two memory slots, allowed to decohere for 2000 ns, then measured. A healthy node (T₂ = 1 s) loses <0.001 fidelity. Node-16 (T₂ = 5 µs) loses ~33% in the same window.
Test 2 — Fiber Delivery Test: For every link on every node, a photon is fired and the Bell pair fidelity measured after traveling through the real fiber channel — capturing the combined effect of attenuation, background noise, and emission quality.
Quality Score: final-score = 0.50 × initial + 0.25 × hw-fidelity + 0.25 × link-fidelity. Node-16 scores ~0.14. Healthy nodes score 0.89–0.96. Any node below the usability threshold is excluded.
Watchdog: Sets LINK-HEALTHY / LINK-DEAD binary alerts per link. Dead links are never used for teleportation.
NodeAssigner: The 8 highest-scoring surviving nodes are assigned to work-0..3 and count-0..3 registers.

— Circuit Execution: Shor-15 —

init: Hadamard gates applied locally to all 4 count qubits — no teleportation needed.
CU0 / CU1: Work and count qubits are teleported to the central switch using EDF scheduling (tightest coherence deadline first). If Bell pair fidelity < 0.92, DEJMPS purification runs using Link B as ancilla — sacrificing a second Bell pair to improve the first. The 5-qubit CU gate is then applied at the switch where all qubits are co-located.
iQFT: Count qubits teleported to switch, all iQFT gates (SWAP, H, CP) applied at the switch, then teleported back.
Measure & Post-Processing: 4 counting qubits measured at leaf nodes. Continued fraction expansion of m/16 gives candidate period r. If r is even and a^(r/2) ≢ -1 mod 15: factor-1 = gcd(a^(r/2)-1, 15), factor-2 = gcd(a^(r/2)+1, 15). Success = {3, 5}.
RecoveryEngine: Each run's result, node assignment, and per-stage fidelity are recorded. Nodes that caused ≥2 failures are blacklisted. The next run's NodeAssigner reads this updated ranking.

— Baseline Comparison —

The baseline (baseline.py) correctly executes all quantum operations — Bell pair generation, BSM, Pauli corrections, gate application — but lacks all SDN intelligence: no Monitor, no Watchdog, no quality scoring, no EDF scheduling, no DEJMPS purification, no RecoveryEngine. It always picks the same nearest nodes regardless of their hardware state. The SDN controller achieved a +7% higher Shor-15 success rate, demonstrating that state-aware orchestration is a fundamental requirement for deep-circuit distributed quantum algorithms.
