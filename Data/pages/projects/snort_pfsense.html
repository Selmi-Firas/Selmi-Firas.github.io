Snort / pfSense IDS-IPS


Designed and deployed a network intrusion detection and prevention system using Snort integrated into pfSense, with Docker containers on Ubuntu as simulated attack targets and Kali Linux in VMware for penetration testing. The project was carried out at Tunisie Telecom and defended in May 2024.

— Problem Statement —

The target enterprise lacked any intrusion detection or prevention capability. Network traffic was unmonitored, leaving the infrastructure exposed to external attacks, port scans, DoS attempts, and unauthorized access. The goal was to deploy a cost-effective, open-source IDS/IPS solution that could detect and block threats in real time without requiring expensive commercial hardware.

— Solution: Snort inside pfSense —

pfSense was selected as the network firewall and gateway — a free, open-source platform that acts as a security guard for the network, controlling inbound and outbound traffic, blocking malicious flows, and enabling secure remote access. It was installed on VirtualBox and configured with LAN and WAN interfaces.

Snort was then installed directly into pfSense via the package manager (System → Package Manager → Installed Packages). Snort operates in three modes:

Sniffer Mode — Reads network packets in real time and displays them in the console. Used for live traffic inspection and initial diagnosis.
Packet Logger Mode — Captures and saves packets to disk for offline forensic analysis and post-incident review.
NIDS Mode — The primary deployment mode. Snort monitors network traffic against a rule set, generates alerts for suspicious patterns, and in IPS mode actively blocks the offending traffic by integrating with pfSense firewall rules.

Custom Snort rules were written and tested to detect specific attack signatures relevant to the environment. The pfSense web dashboard provided a unified view of firewall activity, Snort alerts, and interface traffic statistics.

— Docker Attack Simulation Environment —

Docker was installed on Ubuntu (sudo apt install docker.io) to create lightweight, isolated containers as attack targets — allowing realistic threat simulation without touching production systems. The Docker environment enabled rapid spin-up and teardown of target machines for repeated attack testing cycles. Containers were connected to the monitored network segment so all traffic passed through pfSense and Snort.

— Penetration Testing: Kali Linux in VMware —

Kali Linux was deployed inside VMware as the attacker machine — providing a full suite of pre-installed penetration testing tools for executing controlled attacks against the Docker containers. Attack scenarios executed included port scanning, service enumeration, and network-based exploits. Each attack was monitored in real time through the Snort alert interface inside pfSense, validating that detection rules were correctly triggering and that the IPS mode was blocking malicious traffic.

— Network Architecture —

• pfSense VM — gateway/firewall with LAN and WAN interfaces configured
• Ubuntu VM — internal endpoint running Docker containers as attack targets
• Kali Linux VM (VMware) — attacker machine on the same test network
• All traffic routed through pfSense — giving Snort full visibility over every connection

— Comparison: Security Onion vs Snort/pfSense —

Security Onion is more beginner-friendly with better built-in documentation and a unified web console, making it ideal for teams new to network security monitoring. Snort integrated into pfSense offers greater flexibility and customization — better suited for environments where the firewall and IDS/IPS must share the same device, or where fine-grained rule control is needed. This project demonstrated the pfSense/Snort approach in a live test environment.
