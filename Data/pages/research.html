SDN Controller for Distributed Quantum Computing
Grand Valley State University — Ongoing Research  |  Mentored by Dr. Samah Mansour & Dr. Mostafa El-Said
▶ Overview

Designed and implemented a modular 7-module SDN controller to orchestrate the execution of quantum algorithms across a distributed network of heterogeneous quantum nodes, simulated using the NetSquid discrete-event quantum network simulator. The system was validated by executing Shor's algorithm (N=15) across a 17-node star topology, achieving a +7% improvement in success rate over a hardware-blind greedy baseline.
▶ Network Architecture

A 17-node star topology with randomized, node-specific hardware parameters — T₂ coherence times, SPAM errors, photon emission fidelity, and per-link fiber attenuation — to simulate realistic heterogeneous quantum hardware. One node (Node-16) was force-degraded (T₂ = 5µs) to stress-test the controller's fault-tolerance and recovery mechanisms.
▶ The 7 Controller Modules

Monitor — Active hardware benchmarking: performs a local coherence test (Bell state + 2000ns wait) and an end-to-end fiber delivery test per node. Combines results into a quality score: final-score = 0.50 × initial + 0.25 × hw-fidelity + 0.25 × link-fidelity.
Watchdog — Reads Monitor link records and sets binary LINK-HEALTHY / LINK-DEAD alerts. Dead links are never used for teleportation.
NodeAssigner — Ranks surviving nodes by quality score, applies usability threshold and RecoveryEngine blacklist, then assigns the 8 best nodes to work and count registers.
Translator — Converts circuit stages to network operations. Implements EDF (Earliest Deadline First) scheduling: qubits with the tightest remaining coherence slack are teleported first.
Executioner — Low-level NetSquid API calls: Bell pair generation, BSM at leaf nodes, Pauli corrections at the switch, and gate application.
RecoveryEngine — Cross-run learning: tracks reliability scores (successful-shots / times-used), blacklists nodes that caused ≥2 failures, and re-ranks for the next shot.
Controller — Master orchestrator coordinating all modules across two phases: Boot (hardware scan + node assignment) and Run Loop (circuit execution across all stages).
▶ Shor's Algorithm Execution Flow

init — Hadamard gates applied locally to count-0..3 qubits (no teleportation needed).
CU0 / CU1 — Work and count qubits teleported to the switch using EDF scheduling + DEJMPS purification. 5-qubit CU gate applied at switch. Count qubit teleported back to leaf.
iQFT — All count qubits teleported to switch, iQFT gates (SWAP, H, CP) applied, teleported back.
Measure — 4 counting qubits measured at leaf nodes. Classical post-processing via continued fraction expansion gives candidate period r. If valid: factor-1 = gcd(a^(r/2)−1, 15), factor-2 = gcd(a^(r/2)+1, 15) → {3, 5} = SUCCESS.
▶ DEJMPS Entanglement Purification

When Bell pair fidelity drops below 0.92, DEJMPS purification is triggered: Link B is used as an ancilla, a second Bell pair is sacrificed to improve the first, BSM is performed at the leaf, and Pauli corrections applied at the switch. This inline error-mitigation is a key enabler for deep-circuit execution in noisy environments.
▶ Results

The SDN controller achieved a +7% improvement in Shor-15 success rate over the hardware-blind baseline. The baseline always selected the 5km nodes (lowest attenuation) but had no fidelity management. The SDN controller selected higher-quality nodes regardless of distance and applied purification, demonstrating that managing hardware health via real-time telemetry is just as critical as circuit partitioning strategy.
