Zero Trust Network Access


Designed and deployed a full Zero Trust Network Access (ZTNA) architecture for an enterprise environment, replacing the traditional perimeter-based security model with a "never trust, always verify" approach. Every access request — regardless of source location — is individually authenticated, authorized, and continuously validated.

— Problem Statement —

Analysis of the existing infrastructure revealed critical security gaps: the IT and OT departments shared a flat network with a common IP range, enabling an attacker who compromised one segment to freely move laterally to the other. There were no firewalls, no IDS/IPS, and no access segmentation. Traditional implicit-trust models left the entire network exposed to both internal and external threats — including SQL injection, DoS, Trojans, phishing, and ransomware.

— Architecture —

pfSense (IT Firewall) — Open-source firewall gateway protecting the IT department network. Configured with VLAN rules, traffic filtering, and packet capture. Hosts the Suricata IPS plugin for inline threat prevention.
Cyberoam (OT Firewall) — Dedicated firewall for the Operational Technology department. Configured with OT-specific access policies to isolate industrial and operational systems from IT traffic.
DMZ with Nginx — A demilitarized zone hosting the company's web server, isolated from both the IT and OT networks via Nginx as a reverse proxy. External web traffic is contained within the DMZ and never touches internal resources.
Ruckus Access Points (H500 & ZoneFlex R310) — Managed Wi-Fi infrastructure with separate SSIDs for IT and OT departments, enforced through 802.1X port-based authentication.

— Identity & Access Management (IAM) —

Keycloak — Open-source IAM platform deployed on a Proxmox VM running Java. Configured as a Single Sign-On (SSO) provider managing realms, user groups, and role-based access control (RBAC). Two-Factor Authentication (2FA) enforced via TOTP (time-based one-time password) using authenticator apps — users must complete OTP verification on every login after password entry.
FreeRADIUS — RADIUS authentication server integrating with Keycloak and the Ruckus access points. Handles 802.1X EAP authentication for Wi-Fi — every device connecting to the network must present valid credentials before receiving network access. Configured with custom client.conf and users files; tested and validated via local radtest commands.
Netbird — ZTNA overlay network providing encrypted peer-to-peer tunnels between users/devices and specific authorized resources — not the entire network. Enforces geolocation checks and OS posture verification (e.g., checks OS version and patch level before granting access).

— Monitoring & Visibility —

pfSense Packet Capture was configured to capture and record all traffic on monitored interfaces. Wireshark was used to analyze captured pcap files, verifying encrypted tunnels, authentication exchanges, and detecting any anomalous behavior. The pfSense web dashboard provided real-time interface status, traffic graphs, and firewall rule hit counts.

— ZTNA vs VPN —

Unlike a traditional VPN — which grants a connected user broad access to all network resources — the ZTNA model implemented here grants access only to the specific application or resource the user is authorized for. A compromised VPN credential exposes the entire network; a compromised ZTNA credential exposes only what that specific user was permitted to access.

— Methodology —

The project was managed using Scrum across 4 sprints: planning and architecture design (2 weeks), infrastructure deployment and component configuration (3 weeks), SSO and authentication integration (3 weeks), and final security validation and vulnerability remediation (4 weeks).
